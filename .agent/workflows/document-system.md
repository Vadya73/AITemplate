# Документация подсистемы

Используй при создании или обновлении технического описания механики, интеграции или постоянного контракта.
Для исправления отдельной опечатки дополнительная процедура не нужна.

Начни с подходящего документа через `Docs/INDEX.md`, затем нужных участков кода.
Описание должно объяснять владельца состояния, поток данных, инварианты, ошибки и реальные точки изменения.
Сохраняй полезное описание существующего поведения, отмечай гипотезы и известные ограничения.
Пути `code:` считаются от корня проекта; используй только зависимости, которые действительно описывает документ.

Правила страницы и подключения: [плейбук](../../Docs/_brain/playbooks/document-a-mechanic.md).
После фактической сверки текста выполни `python Scripts/agent.py attest Docs/<имя>.md --reviewed`.
Эта команда записывает дату и отпечатки; запуск генератора сам по себе не подтверждает истинность документа.
Если сверка неполная, оставь `partial` без новой даты, выполни `sync` и перечисли непроверенное.

Заверши `python Scripts/agent.py verify fast`; при ошибках исправь источник, а не генерируемый индекс.
Анализ без разрешения на изменения заканчивается выводами; `attest` и `sync` в нём не запускаются.
