# Second Brain

Точка входа — [INDEX](../INDEX.md); подробные страницы читаются по задаче и диапазонам строк.
Индекс помогает искать контекст, но не заменяет проверку исходников.

## Сборка

```powershell
python -m pip install -r Docs/_brain/requirements.txt
python Scripts/agent.py sync
python Docs/_brain/build.py --check
```

`--check` не записывает файлы и возвращает 1 при битой ссылке, ошибке конфигурации или несовпадении генерируемых результатов.
Сборка сначала рассчитывает результаты и проверяет ссылки, затем записывает только изменившиеся файлы в UTF-8/LF.
Даты запуска, наличие Git и чистота рабочего дерева не влияют на содержимое коммитируемых результатов.
Даты фактической сверки остаются ручным фактом и не обновляются генератором.

## Источники и результаты

| Слой | Источник / результат |
|---|---|
| `brain.yaml` | Домены, документы, hint, стабильные ID/parent, корни кода и карта данных |
| Страницы в `Docs/` | Техническое описание и ручные метаданные |
| `INDEX.md` | Генерируемая навигация и диапазоны строк |
| `registries/` | Генерируемые упоминания, покрытие и актуальность по содержимому |
| `index/symbols.tsv` | Эвристический C#-индекс настроенных корней |
| `DATA.md` | Генерируемая карта вспомогательных данных |
| `glossary.md`, `playbooks/`, `templates/` | Термины, процедуры и заготовки |
| `../Memory/` | Причины решений и текущая незавершённая работа |

Список `docs:` явный, пути считаются от `Docs/`.
Пути `code:` в frontmatter считаются от корня проекта.
Корни `symbols_index.roots` и `coverage.code[].root` считаются от `Docs/`, должны существовать внутри репозитория; пустые списки допустимы.
Подстраница требует существующего родителя и ссылки из него; циклы parent запрещены.
Стабильный `id` можно задать в `brain.yaml`, чтобы переименование не меняло идентичность страницы.

## Сверка с кодом

После фактической проверки документа:

```powershell
python Scripts/agent.py attest Docs/example.md --reviewed
```

Команда фиксирует `verified`, `status: actual` и `verified_code` для зависимостей `code:`, затем пересобирает индекс.
Имя документа в примере заменяется реальным зарегистрированным путём.
Это подтверждение автора, что сверка выполнена; команда не читает смысл документа за человека/агента.
У черновика оставляй `partial` / `missing` и не подтверждай непроверенное.

`Stale.md` сравнивает SHA-256 содержимого с сохранёнными отпечатками и сообщает отсутствующие пути или baseline.
Переводы строк CRLF/LF нормализуются; изменения кода в тот же день обнаруживаются.
Для каталога учитываются имена и содержимое вложенных файлов без типовых кэшей; лучше указывать конкретные зависимости.
Равенство хешей не доказывает правильность текста и не учитывает незарегистрированные зависимости.
Git-история и незакоммиченные изменения доступны отдельно через `python Scripts/agent.py status`, без записи в индексы.

## Метаданные и ограничения

Неизвестные YAML-поля сохраняются.
`id`, `title`, `domain`, `hint`, `side`, `related`, `parent` формируются по источникам; ручные поля и явные реестры описаны в [плейбуке](playbooks/document-a-mechanic.md).
Для произвольных имён используй `tables`, `config_keys`, `resources`, `protocol_keys`, `handlers`; автоматическое извлечение ограничено.
Реестр ID показывает только упоминания, отсутствие в нём не означает свободный номер.
Покрытие означает наличие ссылки, а не полноту документации.

C#-индексатор использует регулярные выражения, возможны пропуски; номера строк проверяй в текущем файле.
Ссылки проверяются на существование относительных файлов/каталогов, включая будущие результаты текущей сборки.
HTTP, якоря и все расширения синтаксиса Markdown не проверяются; автоматической починки по похожему имени нет.
Другие языки ищутся через `rg`/IDE либо отдельный подключённый индексатор.

## Проверки

```powershell
python Scripts/agent.py verify fast
python -B -m unittest discover -s Docs/_brain/tests -v
```

Стандартный Claude Stop-hook проверяет без записи и кеширует успешный результат вне проекта.
В Codex проверки запускаются явно; инструкции подключения — в [SETUP](../agent-rules/SETUP.md).
Оценка поведения самого агента отделена от тестов Python-инфраструктуры: [EVALUATION](../agent-rules/EVALUATION.md).
