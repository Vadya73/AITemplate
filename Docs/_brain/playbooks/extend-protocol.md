# Изменить протокол или формат сохранений

Применяется только если в проекте существует соответствующий контракт.
Не добавляет MessagePack или конкретную схему сериализации в новый проект автоматически.

1. Найди определения контракта, потребителей, хранилище старых данных и команды генерации в текущем репозитории.
2. Установи требования совместимости с выпущенными версиями; неизвестное состояние релиза уточни.
3. Для числовых идентификаторов MessagePack `Union(N)` / `Key(N)` не перенумеровывай существующие значения и не используй удалённые номера повторно.
   Номер нового поля определяется внутри его типа; номер пакета — внутри соответствующего union.
   Сверяй текущий максимум и зарезервированные значения по определениям и истории, а не по числам из старой заметки.
4. [Реестр](../registries/ProtocolKeys.md) показывает упоминания в документах; это не полный список занятых номеров и не автоматическое распределение ID.
5. Учти значения по умолчанию отсутствующих полей, неизвестные поля, чтение старых данных и смешанные версии компонентов.
6. Обнови источник контракта и запусти реальный генератор по правилам проекта; результат генерации вручную не редактируй.
   Если конкретный проект ограничивает запуск, соблюдай его правило из `PROJECT.md`.
7. Проверь появление новых типов/форматтеров в результате и совместимость соответствующими тестами.
8. Обнови описание контракта и пересобери документацию.

См. [документирование](document-a-mechanic.md) и [паспорт проекта](../../agent-rules/PROJECT.md).
