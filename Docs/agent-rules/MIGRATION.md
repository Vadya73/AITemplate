# Источники и решения при переносе

Шаблон собран из пользовательских `AGENTS.md`, `CLAUDE.md`, Second Brain и его генератора, общих настроек `AI_Settings` и родительского Claude Stop-hook.
Источники не изменены; здесь намеренно нет абсолютных путей исходного проекта.

## Перенесено

- Русский язык объяснений, английский код, краткий и конкретный стиль общения.
- Завершение задачи целиком, минимальное исправление, проверка нескольких гипотез и подходящие тесты.
- Запрет прямой работы агента с реальной и локальной БД; код и миграции готовятся файлами.
- Чистый модульный код, SOLID/GRASP, композиция, небольшие сфокусированные файлы, осмысленные комментарии.
- C#-именование и запрет однострочных тел управляющих операторов.
- Unity-композиция, жизненный цикл подписок, serialized-зависимости, раздельные контроллеры и логика.
- Предпочтение живого Editor, CLI при наличии и MCP как альтернативы, явный выбор главного Editor при MPPM.
- Документация в рамках изменения, дата реальной сверки, глоссарий, реестры ловушек и подстраницы.
- Semantic line breaks и пересборка генерируемых документов после разрешения merge-конфликтов.
- Second Brain: домены, подсказки, быстрые секции с диапазонами, граф относительных ссылок, карта данных, символы и актуальность.
- Родительский Stop-hook обобщён на текущий checkout без списка конкретных репозиториев и переведён в проверку без записи.
- Предпочтение тихой работы терминала на Windows.

## Обобщено или разрешено противоречие

| Источник | Решение шаблона |
|---|---|
| Две большие копии правил в AGENTS/CLAUDE | Один общий AGENTS и подключение из CLAUDE |
| Разные форматы сообщений коммитов | Формат — локальная настройка `PROJECT.md`; ни один старый формат не объявлен универсальным |
| Запрос любого неизвестного и обязательный `AskUserQuestion` | Существенные неизвестные уточняются доступным способом; рутинные детали выполняются в рамках согласованной задачи |
| Обязательные 2–3 абзаца рассуждений | Короткий план, если нужен; фиксированный объём внутреннего рассуждения не требуется |
| «100% не сломать» | Проверка реальных контрактов и честный отчёт о непроверенном |
| Odin и `[Header]` в разных файлах | Стандартный Header; Odin только при наличии и проектном соглашении |
| Полный Unity Composition Guide с примерами старых игр | Перенесены общие принципы и процедуры; конкретные классы, сцены и повторы исключены |
| Подразумеваемая автосборка после ответа | Read-only hook, явный sync в разрешённых задачах для обоих агентов |
| Дата из Git/текста использовалась как `verified` | Только явно указанная дата реальной сверки |
| Списки имён таблиц и путей исходной игры в парсере | Явные универсальные метаданные, ограниченное автоматическое извлечение |
| Игнорирование некоторых «общих» файлов при stale-проверке | Проектные исключения по конкретным именам удалены; учитываются все заданные пути |
| Автопочинка ссылок по совпадению имени | Генератор сообщает ошибку, агент исправляет ссылку осмысленно |

## Не переносилось

Название продукта, компания, режимы игры, идентификаторы задач, текущие максимумы/пропуски пакетов, конкретные аккаунты и токены.
Версия Unity/C#/.NET, библиотеки и SDK, структура Assets, названия bootstrap-классов, таймеров, UI, сетевого API и DI.
Entitas/Jenny-ограничения, MessagePack-команды исходной игры, I2-каталог и Google-таблица, имена ресурсов и таблиц БД.
Серверные относительные пути исходной системы, её механики, SQL-сиды, тексты песен, glossary и готовые регистры с игровыми данными.
Claude `settings.local.json`, машинные разрешения, пользовательские плагины, MCP endpoint, локальное окружение и раскладка Obsidian.

Правила совместимости числовых ID и процесса локализации сохранены как условные плейбуки, а не обязательный стек нового проекта.

## Использование исходного генератора

Модули рендеринга, проверки ссылок и эвристического C#-индекса адаптированы из исходного Second Brain.
Оркестратор, frontmatter, универсальные метаданные, покрытие и проверка актуальности переработаны для переносимости и режима без записи.
Версия 2 отделяет текущую Git-диагностику от детерминированных результатов, сравнивает отпечатки кода и добавляет executable-проверки, skills, eval-фикстуры и versioned-обновление.
Тесты используют временные каталоги; изменения исходных репозиториев для проверки не требуются.
