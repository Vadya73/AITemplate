# Настройка нового проекта

Устанавливай из чистого шаблона, сохраняя существующие правила и знания проекта.
Не используй уже заполненную память другой игры как источник нового проекта.

## Адаптация

1. Установи PyYAML: `python -m pip install -r Docs/_brain/requirements.txt`.
2. Используй skill `adapt-project` либо изучи его [процедуру](../../.agent/workflows/adapt-project.md).
3. Заполни [паспорт](PROJECT.md), карту продукта и архитектуру подтверждёнными фактами.
4. В `.agent/project.json` задай имя и тип проекта, `configured`, команды быстрых/полных проверок.
5. Настрой домены, документы и реальные корни исходников в `Docs/_brain/brain.yaml`.
6. Добавь недостающие ignore-правила из [.agent/ignore.example](../../.agent/ignore.example) к существующему `.gitignore`.
7. Выполни `python Scripts/agent.py doctor`, `sync`, затем `verify fast`.

`doctor` читает конфигурацию, но не устанавливает пакеты и не подключается к Editor или БД.
Без продуктовых команд `verify` сообщает о неполной проверке и возвращает 2.
Доступные команды и код возврата описаны в [OPERATIONS](OPERATIONS.md).

## Подключение агентов

Codex использует `AGENTS.md`, Claude импортирует его из `CLAUDE.md`.
Skill-оболочки лежат в `.agents/skills` и `.claude/skills`; содержимое процедур общее, в `.agent/workflows`.
В другом агенте явно укажи прочитать `AGENTS.md`, если он не поддерживает этот файл.
Читай проектный паспорт, архитектуру и гайды по задаче, а не весь набор перед каждой правкой.

В Claude проверь `/context`, обнаружение трёх skills и `/hooks`.
Stop-hook по умолчанию только проверяет; результаты не исправляются автоматически даже после ответа с анализом.
Режим `off` отключает проверку, `enforce: true` включает блокировку завершения при ошибке; этот режим включается осознанно в конкретном проекте.
Кеш успешной проверки лежит в системном временном каталоге, отдельно для каждого checkout/worktree.
Python hook должен видеть тот же PyYAML, что и терминал; при необходимости настрой путь интерпретатора в `.claude/settings.json`.
Проверка Python-скрипта отдельно от Claude не доказывает, что сам Claude его вызывает.

## Obsidian и память

Открой корень проекта как vault; `.obsidian` использует обычные относительные Markdown-ссылки.
При существующем vault объединяй настройки, сохраняя плагины и исключения.
Устойчивые причины решений записывай в [DECISIONS](../Memory/DECISIONS.md), незавершённую работу — в [HANDOFF](../Memory/HANDOFF.md).
Завершённые задачи убирай из handoff; факты о системе сохраняй в соответствующих документах.

## Обновления

Сохраняй `.agent/template-lock.json` в Git: это база безопасного обновления.
Обновляй из чистого шаблона командой установщика `--update`, начиная с `--dry-run`.
Память и проектные файлы с политикой seed сохраняются; обновление не переписывает их новыми заготовками.
Если receipt отсутствует, автоматическое определение внесённых тобой изменений невозможно.
